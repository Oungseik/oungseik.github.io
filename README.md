# sv

## Portfolio

The homepage lives in `src/routes/(portfolio)/+page.svelte`. Edit the featured
projects in `src/lib/projects.ts`; their detail pages are generated at
`/projects/brif-mcp/`, `/projects/bookogsend/`, and `/projects/test-canvas/`. Shared portfolio styles are in
`src/routes/(portfolio)/portfolio.css`, scoped separately from the résumé.

Run `pnpm dev` to preview, `pnpm check` for Svelte/TypeScript diagnostics, and
`pnpm test` to build the static site and verify its page links and content.
The build produces directory indexes for GitHub Pages. Writing is intentionally
not included yet. Newsreader is self-hosted under `static/fonts`, with its OFL license.

Everything you need to build a Svelte project, powered by [`sv`](https://github.com/sveltejs/cli).

## Creating a project

If you're seeing this, you've probably already done this step. Congrats!

```sh
# create a new project
npx sv create my-app
```

To scaffold the same Svelte add-ons in a **new directory**:

```sh
pnpm dlx sv@1.1.0 create --template minimal --types ts --add sveltekit-adapter="adapter:static" enhanced-img mdsvex experimental="features:async,remoteFunctions" ai-tools="ide:other" tailwindcss="plugins:typography,forms" --install pnpm my-app
```

This repository also includes Oxlint and Oxfmt dependencies, configuration files, and
package scripts, which are not generated by the command above.

## Adding features

Add features to your project with `sv add`:

Use `sv add` for an existing project, not `sv create`, which scaffolds a new project.
Keep the existing Vite plugins and SvelteKit options when merging add-on changes.

```sh
npx sv add
```

For example, to add Tailwind CSS:

```sh
npx sv add tailwindcss
```

## Resume preview and PDF

Visit `/resume` to view the single-column A4 resume. Edit the HTML directly in
`src/routes/resume/+page.svelte`; its script only handles preview and pagination.

- Replace bracketed prompts with your details and truthful achievements.
- Edit the role and specialization in `<p class="professional-title">` to match
  the position you are applying for.
- Edit contact links directly in their `<a href="...">` elements. Use
  `mailto:you@example.com` for email, `tel:+...` for phone, and full `https://`
  URLs for LinkedIn, GitHub, your portfolio, and project links. The profile links
  are populated; project placeholders remain plain text until you add their URLs.
- Keep experience and education newest first. Duplicate a `<div class="entry">`
  to add a role, project, or qualification; remove entries you do not need.
- Remove the corresponding `<section>` to omit an optional section. Delete
  unused contact details and skill paragraphs directly from the markup.
- Use each role's paragraph below the company for product, user, or ownership
  context; remove it if unnecessary. Keep bullets focused on action, approach,
  and outcome.
- Use verified metrics only. If numbers are unavailable, describe a concrete
  capability or result rather than inventing a measurement.

The outline includes two roles, four skill groups, one project, and one education
entry. It is edited in source, not through an in-browser form.

The document uses a 210 × 297 mm page, 11 pt Arial body text with a 1.5 line height,
and 18 mm internal margins. The name is 28 pt, section headings are 13.5 pt, and
entry titles are 11.5 pt. Sections have 6 mm separation, with 2 mm between each
section heading and its content and 4 mm between entries.
Narrow screens scale the preview without changing line wrapping; printing restores
the document to full size.

Arial/Helvetica is intentional: `resume-guidelines.md` recommends familiar,
readable typefaces. Keeping fonts local avoids a web-font loading dependency in
the preview and PDF output.

Paged.js 0.4.3 does not ship TypeScript declarations. `src/pagedjs.d.ts` describes
the API used by the preview; keep it aligned when upgrading the paginator.
Keyboard focus on a resume link is preserved when the source is replaced by the
paginated preview.

Use **Print / Save PDF** or the browser's print command with these settings:

- Destination: **Save as PDF**
- Paper size: **A4**, portrait
- Scale: **100%**
- Margins: **None** (the resume already includes its own margins)
- Headers and footers: **Off**

The preview toolbar, instructions, workspace, and paper shadow are not printed.
The placeholder content fits one page. Substantial additions can create more printed
pages; trim lower-priority content rather than reducing the font size.

## Linting and formatting

```sh
pnpm lint         # Run Oxlint
pnpm lint:fix     # Apply safe lint fixes
pnpm format       # Format files with Oxfmt
pnpm format:check # Check formatting without writing
pnpm check        # Run Svelte and TypeScript diagnostics
```

Oxlint uses its default correctness rules with warning severity. It checks JavaScript,
TypeScript, and Svelte `<script>` blocks, not Svelte templates; keep running `pnpm check`.
The scaffold's empty `src/lib/index.ts` currently produces a `unicorn/no-empty-file` warning.

Oxfmt preserves the project's tabs, single quotes, and omitted trailing commas.
Svelte formatting is enabled with `"svelte": true` in `.oxfmtrc.json`; it requires
this project's installed `svelte` package, but no separate Prettier dependency.
Both tools respect `.gitignore` and explicitly exclude `.svelte-kit` and `build`.
Oxfmt also skips lockfiles. `pnpm format` formats Markdown notes too; the existing
`resume-guidelines.md` and `tech-industry-research.md` have not been reformatted during setup.

## Included features

- Tailwind CSS 4, including the forms and typography plugins, imported by the root layout.
- Enhanced images via `@sveltejs/enhanced-img`.
- Markdown components via mdsvex (`.svx` and `.md`).
- Experimental async Svelte and SvelteKit remote functions.
- Static generation via `@sveltejs/adapter-static` and root-layout prerendering.
- Oxlint and Oxfmt for linting and formatting.

## Building

To create a production version of your app:

```sh
npm run build
```

You can preview the production build with `npm run preview`.

The static adapter writes the prerendered site to `build`. Remote-function support is
enabled, but request-time queries, forms, and commands require a server and cannot run
on a static host such as GitHub Pages. Use remote `prerender` functions for static data.
